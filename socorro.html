Vim Estou Preso no Vim!

Respire: você não está preso. O Vim só não sai com Ctrl+q nem com o "X" da janela como outros programas. Esta página é o mapa de emergência: primeiro o roteiro que resolve 95% dos casos, depois cada situação estranha, com o que aconteceu e como sair.

Você vai aprender
  • O roteiro de três passos para sair de qualquer modo.
  • O que fazer quando a tela congela, quando aparece "gravando" ou quando as teclas fazem coisas estranhas.
  • Como responder ao aviso E325: ATENÇÃO do arquivo de troca.
  • O que fazer quando o Vim abre sozinho (git, crontab) e quando ele "some" com Ctrl+z.

O roteiro de emergência

  1. Aperte Esc duas vezes. Isso sai do modo de inserção, do modo visual e cancela comandos pela metade. Não faz mal apertar a mais.
  2. Digite :q! e aperte Enter. Você vai ver o :q! aparecer no rodapé enquanto digita. Isso sai sem salvar.
  3. Quer guardar o que fez? Em vez de :q!, digite :wq e Enter: salva e sai.

Treino livre: faça as bagunças sugeridas no texto e pratique o roteiro. Reparou que Esc Esc sempre leva de volta a um rodapé limpo? Use Reiniciar para repetir.

A tela congelou e nada responde

Apertei Ctrl+S (o "salvar" de outros programas) e tudo travou

O que aconteceu: no terminal, Ctrl+s é um comando antigo de "controle de fluxo": ele pausa a saída do terminal. O Vim continua funcionando, mas a tela parou de ser atualizada.

Como resolver: aperte Ctrl+q. A tela volta, e tudo o que você digitou durante a pausa aparece de uma vez. Para desativar esse comportamento no terminal, acrescente stty -ixon ao seu ~/.bashrc.

A tela ficou cheia de lixo ou desalinhada

O que aconteceu: outro programa escreveu no terminal por cima do Vim, ou a janela mudou de tamanho no meio de algo.

Como resolver: Ctrl+l manda o Vim redesenhar a tela.

O rodapé mostra algo estranho

Aparece "gravando @q" no rodapé

O que aconteceu: você apertou q seguido de uma letra (por exemplo, tentando digitar :q sem os dois-pontos). Isso começa a gravar uma macro: o Vim está anotando cada tecla.

Como resolver: aperte q mais uma vez, no modo normal, para parar a gravação. Nada foi alterado só por gravar.

Texto qualquer.
Aparece uma janela pequena com comandos antigos no pé da tela

O que aconteceu: você digitou q: (em vez de :q). Isso abre a "janela da linha de comando", com o histórico dos seus comandos. Se tentar sair errado, aparece E11: Inválido na janela da linha de comando; <CR> executa, CTRL-C sai.

Como resolver: digite :q e Enter para fechar só essa janelinha, ou aperte Ctrl+c duas vezes.

Aparece "Entrando no modo Ex. Digite "visual" para ir para o modo Normal."

O que aconteceu: você apertou Q (maiúsculo) e entrou no modo Ex, uma linha de comando contínua, herança do editor ex.

Como resolver: digite visual e Enter para voltar à tela normal. Ou saia direto com q! e Enter (aqui sem os dois-pontos).

Apertei Ctrl+C e apareceu "Digite :qa! e aperte <Enter> para abandonar as alterações e sair do Vim"

O que aconteceu: o Vim percebeu que você está tentando sair "à força" e deixa a dica.

Como resolver: siga a dica: :qa! e Enter sai de todos os arquivos abertos sem salvar.

As teclas fazem coisas inesperadas

Cada tecla faz uma coisa diferente do que deveria

O que aconteceu: o Caps Lock está ligado. No Vim, maiúscula e minúscula são comandos diferentes: j desce, mas J junta linhas; u desfaz, mas U desfaz a linha inteira; K abre o manual (man) da palavra sob o cursor.

Como resolver: desligue o Caps Lock, aperte Esc e desfaça os estragos com u. Se o K abriu um manual, saia dele com q.

Digito e não acontece nada, mas o canto direito do rodapé mostra letras

O que aconteceu: há um comando pela metade esperando continuação (por exemplo d, 2 ou "a).

Como resolver: Esc cancela o comando pendente.

E325: ATENÇÃO — o arquivo de troca

Enquanto você edita, o Vim guarda suas alterações num arquivo escondido ao lado do original, o arquivo de troca (swap file), com nome como .notas.txt.swp. Numa saída normal ele é apagado. Se ele ainda existe quando você abre o arquivo, o Vim para e avisa:

$ vim notas.txt
E325: ATENÇÃO
Foi encontrado um arquivo de troca de nome ".notas.txt.swp"
        pertence a: ana   com data: qui out 15 10:12:44 2026
   nome do arquivo: ~ana/notas.txt
        modificado: SIM
   nome de usuário: ana   nome do host: notebook
    ID do processo: 4321
Ao abrir o arquivo "notas.txt"
       com data de: qui out 15 10:05:11 2026

(1) Outro programa pode estar editando o mesmo arquivo. Se for esse
    o caso, cuidado para não acabar com duas versões do mesmo arquivo
    ao fazer alterações. Saia, ou continue com cuidado.
(2) Uma sessão de edição para esse arquivo travou.
    Se for esse o caso, use ":recover" ou "vim -r notas.txt"
    para recuperar as alterações (veja ":help recovery").
    Se você já vez isso, exclua o arquivo de troca ".notas.txt.swp"
    para evitar esta mensagem.

O arquivo de troca ".notas.txt.swp" já existe!
[A]brir somente-leitura, (E)ditar mesmo assim, (R)ecuperar, E(x)cluí-lo, (S)air, (C)ancelar:

O "vez" no lugar de "fez" está assim na tradução oficial do Vim. As datas variam conforme o sistema. As duas causas possíveis estão escritas na própria mensagem: (1) o arquivo já está aberto em outro Vim, ou (2) um Vim anterior fechou de forma anormal (terminal fechado, queda de energia, SSH caiu).

Qual resposta escolher

TeclaOpçãoQuando usar
AAbrir somente-leituraVocê só quer olhar o arquivo.
EEditar mesmo assimVocê tem certeza de que não há outro Vim aberto e não quer recuperar nada.
RRecuperarO Vim anterior travou e você quer de volta o que não foi salvo.
xExcluí-loApaga o arquivo de troca. Só aparece quando o processo que o criou já não está rodando.

No Vim em inglês as letras são outras: [O]pen Read-Only, (E)dit anyway, (R)ecover, (D)elete it, (Q)uit, (A)bort. Leia sempre a linha de opções antes de apertar.

Recuperando depois de um travamento

  1. Aperte R. O Vim mostra Recuperação concluída. Você deve verificar se está tudo certo.
  2. Confira o texto. Se estiver bom, salve com :w.
  3. O arquivo de troca antigo continua lá. Saia (:q), abra de novo e, no aviso, escolha x (Excluí-lo). Ou apague pelo terminal: rm .notas.txt.swp.
$ vim -r
$ vim -r notas.txt

O vim -r sozinho lista os arquivos de troca encontrados; com o nome do arquivo, abre já recuperando.

O Vim abriu sozinho

Rodei git commit e caí no Vim

O que aconteceu: o git abre o editor padrão do sistema para você escrever a mensagem do commit. Em muitos sistemas, esse editor é o Vim.

Como resolver: aperte i, escreva a mensagem na primeira linha, Esc e :wq. Para cancelar o commit, saia com :cq: ele sai com código de erro, e o git desiste. Para trocar o editor do git: git config --global core.editor nano.



# Escreva a mensagem do commit. Linhas começando com '#' são ignoradas.
#
# No ramo main
# Mudanças a serem submetidas:
#	modificado:   login.py
Corrige erro no login
# Escreva a mensagem do commit. Linhas começando com '#' são ignoradas.
#
# No ramo main
# Mudanças a serem submetidas:
#	modificado:   login.py

Missão: o git abriu o Vim. Escreva Corrige erro no login na primeira linha (que está vazia) e saia salvando com :wq. (As linhas com # imitam as instruções do git; o texto real depende da versão e do idioma.)

crontab -e, visudo ou outro comando abriu o Vim

O que aconteceu: esses comandos usam a variável EDITOR, ou perguntam qual editor usar na primeira vez.

Como resolver: para escolher outro editor só desta vez: EDITOR=nano crontab -e. Para sempre: export EDITOR=nano no ~/.bashrc. No Debian e no Ubuntu, select-editor refaz a pergunta do crontab.

$ EDITOR=nano crontab -e
$ git config --global core.editor nano

O Vim sumiu

Apertei Ctrl+Z e voltei para o terminal

O que aconteceu: Ctrl+z suspende o programa e devolve o terminal. O Vim continua vivo, pausado, com tudo o que você fez.

Como resolver: digite fg (de foreground) para voltar a ele.

$ vim notas.txt
[1]+  Parado                  vim notas.txt         « depois do Ctrl+Z
$ fg
Não abra o mesmo arquivo de novo

Se você esquecer o Vim suspenso e abrir vim notas.txt outra vez, vai ver o aviso E325 da seção acima: o arquivo de troca é do Vim pausado. Escolha S (Sair) e use fg. O comando jobs mostra os programas suspensos.

Resumo

  • Roteiro: Esc Esc, depois :q! (sair sem salvar) ou :wq (salvar e sair).
  • Tela congelada: Ctrl+q. "gravando": q. Modo Ex: visual.
  • E325 avisa que existe um arquivo de troca: leia as opções; R recupera depois de um travamento.
  • :cq sai com erro (cancela o commit do git).
  • Ctrl+z só pausa o Vim: fg traz de volta.
