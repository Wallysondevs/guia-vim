Vim Autocomandos

Um autocomando é uma regra do tipo "quando acontecer tal coisa, faça isto": quando eu salvar, tire os espaços do fim das linhas; quando abrir um arquivo Python, use recuo de 4 espaços. Você escreve a regra uma vez no .vimrc e o Vim cuida do resto.

Você vai aprender
  • Ler e escrever um autocmd: evento, padrão e comando.
  • Os eventos mais úteis: BufWritePre, FileType, BufReadPost, BufNewFile.
  • Por que todo autocomando deve ficar dentro de um augroup com autocmd!.
  • Receitas prontas para o seu .vimrc.
  • Como listar e investigar autocomandos.
Antes de começar

Autocomandos ficam no .vimrc e usam um pouco de Vimscript. Eles precisam do Vim completo (o pacote vim); o vim-tiny que vem em alguns sistemas não tem esse recurso.

Esta aula é para o Vim real

O Vim simulado deste guia não roda autocomandos. Onde aparece uma demonstração, ela mostra o comando que o autocomando executa.

Anatomia de um autocomando

autocmd
Cria uma regra automática (pode ser abreviado como au).
BufWritePre
O evento: quando ela dispara. Aqui, logo antes de gravar o arquivo (buffer write, pre).
*.py
O padrão: para quais arquivos. Aqui, os que terminam em .py. Use * para todos.
%s/\s\+$//e
O comando: qualquer comando :. Aqui, uma substituição que apaga espaços no fim das linhas.
autocmd BufWritePre *.py %s/\s\+$//e

Lendo em voz alta: "antes de gravar qualquer arquivo .py, troque os espaços do fim das linhas por nada". Veja o que essa substituição faz num arquivo. A opção list está ligada para mostrar o fim de cada linha como $, assim você enxerga os espaços sobrando:

nome = "ana"   
idade = 30  
cidade = "Recife"

O e no fim do :s é importante num autocomando: ele diz "se não achar nada, fique quieto". Sem ele, todo arquivo já limpo mostraria E486: Padrão não encontrado a cada vez que você salvasse.

Os eventos mais usados

O Vim tem mais de cem eventos (veja :help autocmd-events). Estes resolvem a maioria dos casos:

EventoDispara quando…Uso típico
BufReadPostUm arquivo existente acabou de ser lidoVoltar à última posição do cursor
BufNewFileVocê abre um arquivo que ainda não existeInserir um modelo
BufWritePreAntes de gravarLimpar espaços, formatar
BufWritePostDepois de gravarRecarregar a configuração, rodar um teste
FileTypeO Vim descobriu o tipo do arquivo (python, markdown…)Opções por linguagem
BufEnter / BufLeaveVocê entra ou sai de um bufferMudar a pasta atual, salvar ao sair
InsertEnter / InsertLeaveEntra ou sai do modo de inserçãoMudar a aparência da linha do cursor
VimEnter / VimLeaveO Vim terminou de abrir / vai fecharAbrir um painel, salvar a sessão
TextYankPostLogo depois de copiar com yCopiar também para outro lugar

O padrão

Para eventos de arquivo, o padrão é um curinga de nome: *.md, *.{js,ts}, /etc/*, *. Para o FileType, o padrão é o nome do tipo, sem asterisco: python, markdown, sh. Para saber o tipo do arquivo aberto, use :set filetype?.

O problema da duplicação, e o augroup

Cada vez que o .vimrc é lido, o autocmd cria uma regra nova, mesmo que igual a uma existente. Se você recarrega a configuração com :source ~/.vimrc três vezes, a substituição passa a rodar três vezes a cada gravação. Com comandos mais pesados, o Vim fica lento sem motivo aparente.

A solução é colocar os autocomandos num grupo e limpar o grupo antes de recriá-los:

augroup meu_vimrc
Começa (ou reabre) um grupo com esse nome.
autocmd!
Com ! e sem mais nada: apaga todos os autocomandos deste grupo.
autocmd …
Recria as regras, agora sem duplicar.
augroup END
Fecha o grupo.
augroup meu_vimrc
  autocmd!
  autocmd BufWritePre *.py,*.js,*.sh %s/\s\+$//e
augroup END
Sempre use um augroup

Trate o par augroup + autocmd! como parte obrigatória da sintaxe. Ele não custa nada e evita um dos problemas mais comuns e difíceis de perceber no Vim.

Receitas

Opções por linguagem com FileType

Python pede 4 espaços de recuo; Makefile exige tabulação de verdade; texto em Markdown fica melhor com quebra de linha visual e corretor ortográfico. Use setlocal, e não set, para a opção valer só naquele arquivo:

filetype plugin indent on

augroup por_linguagem
  autocmd!
  " Python: recuo de 4 espaços
  autocmd FileType python setlocal shiftwidth=4 softtabstop=4 expandtab
  " Makefile precisa de tabs de verdade
  autocmd FileType make setlocal noexpandtab
  " Markdown: quebra de linha na tela e verificação ortográfica em português
  autocmd FileType markdown setlocal wrap linebreak spell spelllang=pt_br
  " YAML: 2 espaços
  autocmd FileType yaml setlocal shiftwidth=2 expandtab
augroup END

A primeira linha liga a detecção de tipos. Ela já vem ligada quando você usa o Vim sem .vimrc (pelo defaults.vim), mas é bom deixá-la explícita no seu arquivo.

Voltar para onde você parou

Ao reabrir um arquivo, o Vim pode levar o cursor à posição em que ele estava quando você saiu. Ele guarda essa posição na marca " (veja Marcas e Saltos):

augroup ultima_posicao
  autocmd!
  " Pula para a marca '" se ela existir e não for uma mensagem de commit
  autocmd BufReadPost *
    \ if line("'\"") >= 1 && line("'\"") <= line("$") && &ft !~# 'commit'
    \ |   exe "normal! g`\""
    \ | endif
augroup END

As linhas que começam com \ continuam a linha de cima. Esta receita é a mesma que o defaults.vim do Vim 9 já usa, então ela só é necessária se você criou um .vimrc sem carregar o defaults.vim.

Modelo para arquivos novos

Todo script novo começar com o cabeçalho certo:

#!/usr/bin/env bash
set -euo pipefail

augroup modelos
  autocmd!
  " Ao criar um .sh que não existe, lê o modelo para a linha 0 (o topo)
  autocmd BufNewFile *.sh 0r ~/.vim/modelos/script.sh
augroup END

Recarregar o .vimrc ao salvá-lo

augroup recarrega_vimrc
  autocmd!
  autocmd BufWritePost $MYVIMRC source $MYVIMRC
augroup END

Aqui o augroup é indispensável: cada recarga lê o arquivo de novo, e sem o autocmd! as regras se multiplicariam a cada gravação.

Limpar espaços sem o cursor pular

O %s deixa o cursor na última linha alterada, o que irrita ao salvar. Uma pequena função guarda a posição da tela e devolve depois (as funções são explicadas em Vimscript Básico):

function! s:LimpaEspacos()
  let l:visao = winsaveview()
  keeppatterns %s/\s\+$//e
  call winrestview(l:visao)
endfunction

augroup limpa_espacos
  autocmd!
  autocmd BufWritePre * call s:LimpaEspacos()
augroup END

O keeppatterns impede que essa substituição vire a "última busca", que o n repetiria.

Quando não funciona

O comando roda duas, três, dez vezes

O que aconteceu: o .vimrc foi recarregado e o autocomando não estava num augroup com autocmd!.

Como confirmar: :autocmd BufWritePre mostra a mesma regra repetida.

Como resolver: envolva no par augroup/autocmd! e reinicie o Vim.

"E216: Evento inexistente"

O que aconteceu: erro de digitação no nome do evento, como BufWritPre. No Vim em inglês: E216: No such event.

Como resolver: confira o nome em :help autocmd-events. Maiúsculas não importam (bufwritepre funciona), mas cada letra precisa estar lá.

Toda vez que salvo aparece "E486: Padrão não encontrado"

O que aconteceu: a substituição do autocomando não tem a flag e, e o arquivo não tinha nada para trocar.

Como resolver: acrescente e ao fim: %s/\s\+$//e.

O FileType python não faz efeito

O que aconteceu: a detecção de tipos está desligada, ou o arquivo não foi reconhecido como Python.

Como confirmar: :set filetype? deve responder filetype=python.

Como resolver: coloque filetype plugin indent on no começo do .vimrc. Para um arquivo sem extensão, defina na mão: :set filetype=python.

Mudei uma opção no FileType e ela afetou todos os arquivos

O que aconteceu: foi usado set em vez de setlocal. O set muda o valor global, que os próximos arquivos herdam.

Como resolver: troque por setlocal.

Resumo

  • autocmd {evento} {padrão} {comando}: quando o evento acontecer em arquivos do padrão, rode o comando.
  • BufWritePre (antes de salvar), FileType (por linguagem), BufReadPost e BufNewFile resolvem a maioria dos casos.
  • Sempre dentro de augroup nome + autocmd! + augroup END.
  • Em autocomandos de tipo, use setlocal; em substituições, a flag e.
  • :verbose autocmd mostra o que está ativo e de onde veio.
