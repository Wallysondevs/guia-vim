Vim Solução de Problemas

Quase todo susto no Vim tem uma causa simples: você está num modo diferente do que pensa, o terminal fez algo por conta própria, ou falta um recurso na sua versão do Vim. Cada problema abaixo tem o sintoma (com a mensagem em português e em inglês), a causa e a solução.

Primeiros socorros, para qualquer situação

Aperte Esc duas vezes, digite :q! e Enter. Você sai do Vim sem salvar nada e pode recomeçar com calma. Se nem isso funcionar, veja A tela congelou.

Sair e travar

Não consigo sair do Vim

Sintoma: você digita exit, quit ou Ctrl+C e nada acontece, ou as palavras aparecem no meio do texto. O Ctrl+C mostra:

Digite  :qa!  e aperte <Enter> para abandonar as alterações e sair do Vim
(inglês: Type  :qa!  and press <Enter> to abandon all changes and exit Vim)

Causa: no Vim, sair é um comando da linha de comando, e só funciona a partir do modo normal.

Solução: Esc e depois :q Enter. Se houver alterações, :wq salva e sai; :q! sai sem salvar. Veja Abrir e Sair.

A tela congelou: nada que eu digito aparece

Sintoma: o Vim parece morto. Nenhuma tecla responde.

Causa: você apertou Ctrl+S (o "salvar" de outros editores). No terminal, essa tecla pausa a tela. O Vim continua recebendo o que você digita, só não mostra.

Solução: aperte Ctrl+Q para despausar. Tudo o que você digitou durante a pausa aparece de uma vez; se algo estranho acontecer, use u para desfazer. Para salvar, use :w. Veja Estou Preso no Vim!.

Apareceu "gravando @q" no rodapé 
gravando @q
(inglês: recording @q)

Causa: você apertou q e outra tecla, o que inicia a gravação de uma macro. Tudo o que você digitar fica gravado.

Solução: aperte q de novo (no modo normal) para parar. Nada foi estragado; a gravação só guarda teclas. Para que serve isso, veja Macros.

O Vim virou uma linha de comando com ":" e não mostra mais o arquivo 
Entrando no modo Ex.  Digite "visual" para ir para o modo Normal.
:
(inglês: Entering Ex mode.  Type "visual" to go to Normal mode.)

Causa: você apertou Q (maiúsculo) ou gQ, que entra no modo Ex, o editor de linha antigo.

Solução: digite vi (ou visual) e Enter. Volta tudo ao normal. Veja Estou Preso no Vim!.

O Vim sumiu e voltei para o terminal, com a mensagem "Parado" 
$ vim notas.txt
[1]+  Parado                  vim notas.txt

Causa: Ctrl+Z suspende o programa e devolve o terminal. O Vim continua aberto, em segundo plano, com suas alterações.

Solução: digite fg e Enter no terminal para voltar ao Vim. Veja Integração com o Shell.

Salvar

E37 ao tentar sair 
E37: Alterações não foram gravadas (adicione ! para forçar)
(inglês: E37: No write since last change (add ! to override))

Causa: o arquivo tem alterações não salvas, e o :q se recusa a jogá-las fora.

Solução: :wq para salvar e sair, ou :q! para sair descartando. O ! é o "tenho certeza". Veja Salvar e Sair.

E45 ao salvar 
E45: opção 'readonly' está definida (adicione ! para forçar)
(inglês: E45: 'readonly' option is set (add ! to override))

Causa: o arquivo foi aberto só para leitura: com view, vim -R, ou ao escolher "Abrir somente-leitura" no aviso de arquivo de troca.

Solução: se você tem permissão de escrita, :w! grava mesmo assim. Se o arquivo é de outro usuário, veja o próximo problema.

E212 ao salvar um arquivo do sistema 
"/etc/hosts" E212: Impossível abrir arquivo para escrita
(inglês: E212: Can't open file for writing)

Causa: você editou um arquivo do root (como /etc/hosts) sem sudo. Seu usuário não pode gravá-lo.

Solução: sem perder o que digitou, rode:

:w !sudo tee % > /dev/null

O :w ! manda o texto para um comando, o sudo tee grava com permissão de root e % é o nome do arquivo atual. Depois, :q!. Da próxima vez, abra com sudoedit /etc/hosts. Veja Salvar e Sair.

E325: ATENÇÃO ao abrir um arquivo 
E325: ATENÇÃO
Foi encontrado um arquivo de troca de nome ".notas.txt.swp"
…
Ao abrir o arquivo "notas.txt"
…
[A]brir somente-leitura, (E)ditar mesmo assim, (R)ecuperar, E(x)cluí-lo, (S)air, (C)ancelar:
(inglês: E325: ATTENTION / Found a swap file by the name ".notas.txt.swp")

Causa: existe um arquivo .swp do mesmo arquivo. Ou o Vim fechou de forma inesperada (queda de energia, terminal fechado), ou o arquivo já está aberto em outro terminal.

Solução:

  1. Se o arquivo está aberto em outro terminal: aperte S (sair) e use o outro.
  2. Se o Vim caiu e você quer o trabalho de volta: R (recuperar), confira o texto, salve com :w e depois apague o .swp (o próximo aviso oferece x para excluí-lo).
  3. Se não há nada a recuperar: x (excluí-lo) e siga normalmente.

Veja Estou Preso no Vim!.

E32 ao salvar 
E32: Nenhum nome de arquivo
(inglês: E32: No file name)

Causa: você abriu o Vim sem nome de arquivo (só vim) e tentou :w.

Solução: dê um nome: :w notas.txt.

Digitar

Digitei comandos e eles viraram texto

Sintoma: você digitou dd e apareceu "dd" no arquivo. O rodapé mostra -- INSERÇÃO -- (inglês: -- INSERT --).

Causa: você estava no modo de inserção, em que toda tecla vira texto.

Solução: Esc para voltar ao modo normal e u para desfazer o texto digitado por engano. Veja Os Modos do Vim.

Os comandos fazem coisas estranhas: j junta linhas, u desfaz demais

Causa: o Caps Lock está ligado. No Vim, maiúscula é outro comando: J junta linhas, U desfaz a linha, D apaga até o fim, K abre a página de manual.

Solução: desligue o Caps Lock e use u até voltar ao estado certo. Se o K abriu um manual, saia dele com q.

Primeira linha. Segunda linha.
terceira linha
Primeira linha.
Segunda linha.
terceira linha

Missão: alguém apertou J com o Caps Lock ligado e juntou duas linhas. Separe-as de novo: leve o cursor ao espaço antes de "Segunda" e troque esse espaço por uma quebra de linha.

Ver uma solução

f. leva ao primeiro ponto; l anda até o espaço; r + Enter troca o espaço por uma quebra de linha.

Colar texto no terminal bagunça o recuo (cada linha vai mais para a direita)

Causa: ao colar no terminal com Ctrl+Shift+V, o Vim recebe o texto como se você digitasse muito rápido, e o recuo automático soma recuo a cada linha. Vims recentes reconhecem a colagem ("bracketed paste") e evitam isso, mas terminais antigos ou SSH podem não avisar.

Solução: antes de colar, :set paste; depois, :set nopaste. Melhor ainda: se o Vim tem +clipboard, cole com "+p no modo normal. Veja Área de Transferência e Inserir Texto.

As setas escrevem A, B, C, D no modo de inserção

Causa: o Vim está em modo compatível com o vi antigo (compatible), que não entende os códigos que o terminal manda para as setas. Acontece com o vim-tiny sem .vimrc ou quando o Vim abre com -u NONE.

Solução: crie um ~/.vimrc (mesmo vazio, ele liga nocompatible) ou digite :set nocompatible. Instalar o pacote vim completo também resolve. Veja .vimrc Básico.

O Backspace não apaga o que já estava escrito

Causa: a opção backspace está vazia (comportamento do vi antigo): ele só apaga o que você digitou desde que entrou no modo de inserção, e não passa para a linha de cima.

Solução: no .vimrc, set backspace=indent,eol,start. O defaults.vim já faz isso quando você não tem .vimrc. Veja Opções Úteis.

O Tab insere 8 espaços (ou um tab de verdade) e meu código usa 4

Causa: os padrões do Vim são tabstop=8, shiftwidth=8 e noexpandtab.

Solução: no .vimrc: set expandtab shiftwidth=4 tabstop=4 softtabstop=4. Para ver tabs e espaços no fim das linhas, :set list. Para converter um arquivo inteiro, :retab. Veja Opções Úteis.

Texto e tela

Acentos aparecem como "Ã§" ou "<e7>"

Causa: o arquivo está numa codificação (como Latin-1, comum em arquivos antigos do Windows) e o Vim leu como UTF-8, ou o terminal não está em UTF-8.

Solução: reabra informando a codificação: :e ++enc=latin1. Para converter e salvar em UTF-8: :set fileencoding=utf-8 e :w. Confira o terminal com locale no shell (deve mostrar UTF-8). Ao gravar, o Vim pode avisar [ERRO DE CONVERSÃO na linha N] (inglês: [CONVERSION ERROR in line N]).

Cores estranhas, texto ilegível ou sem cor nenhuma

Causa: o tema de cores não combina com o fundo do terminal, ou o realce de sintaxe está desligado, ou seu Vim é o vim-tiny, que não tem cores.

Solução: :set background=dark (ou light) ajusta as cores ao fundo; :syntax on liga o realce; :colorscheme + espaço + Tab mostra os temas instalados. Um tema inexistente dá E185: Esquema de cores 'x' não encontrado. Veja .vimrc Básico.

E492 ao digitar um comando 
E492: Não é um comando do editor: wq1
(inglês: E492: Not an editor command)

Causa: erro de digitação depois do :, ou um comando de plugin que não está instalado.

Solução: digite : e use a seta ↑ para ver e corrigir o comando anterior. Veja Mensagens e Erros Comuns.

A busca não acha "1+1" nem "(texto)"

Causa: nas expressões regulares do Vim, alguns caracteres têm sentido especial e outros só têm com barra. ., *, [, ^ e $ são especiais; + e ( são literais, e viram especiais com \ na frente.

Solução: para achar um ponto literal, use \.; para um * literal, \*. Para buscar sem nenhum caractere especial, use \V no começo: /\V1+1. Veja Expressões Regulares do Vim.

O :s diz que não achou, mas o texto está ali 
E486: Padrão não encontrado: a.b
(inglês: E486: Pattern not found: a.b)

Causa: uma diferença de maiúsculas, um caractere especial (veja o problema anterior) ou a faixa errada: :s sem % só olha a linha atual.

Solução: use :%s para o arquivo inteiro; \c no padrão ignora maiúsculas; teste antes com /padrão para ver o que casa. Para não ver o erro em macros e scripts, a flag e: :%s/x/y/ge. Veja Substituir.

Desfazer

Apaguei um trecho, depois apaguei outra coisa, e quero o primeiro de volta

Causa: o p cola só o último apagado. Mas o Vim guarda os nove últimos trechos de linhas apagados nos registradores "1 a "9.

Solução: "1p cola o último; se não for o que você queria, u e . (o ponto troca para o "2, depois o "3…). :reg mostra todos. E u sempre desfaz o apagamento. Veja Registradores.

linha importante
lixo 1
lixo 2
fim
lixo 1
lixo 2
fim
linha importante

Missão: apague a "linha importante" com dd, depois apague "lixo 1" e "lixo 2" com mais dois dd. Agora recupere a linha importante e cole-a depois de "fim", sem usar u.

Ver uma solução
  1. dd três vezes apaga as três primeiras linhas; o cursor fica em "fim". Os registradores agora guardam: "1 = "lixo 2", "2 = "lixo 1", "3 = "linha importante" (o mais antigo vai ficando para trás).
  2. "3p cola a "linha importante" abaixo de "fim".
  3. gg volta ao topo; "1P cola "lixo 2" acima; "2P cola "lixo 1" acima dele.
Desfiz demais com u

Solução: Ctrl+r refaz. Se você desfez, mudou algo e quer uma versão antiga, :earlier 5m volta o arquivo a como estava 5 minutos atrás. A mensagem do desfazer mostra quanto você voltou: 1 alteração; antes de #4 12 segundos atrás. Veja Desfazer e Refazer.

Configuração e versão

Erro ao abrir o Vim, mostrando uma linha do .vimrc 
Erro detectado ao processar /home/ana/.vimrc:
linha   12:
E518: Opção desconhecida: shitwidth=4
Aperte ENTER ou digite um comando para continuar
(inglês: Error detected while processing /home/ana/.vimrc: / E518: Unknown option)

Causa: erro de digitação ou comando que sua versão não tem, na linha indicada do .vimrc.

Solução: Enter para continuar, :e $MYVIMRC para abrir o arquivo, :12 para ir à linha e corrigir. Para testar sem configuração: vim --clean. Veja .vimrc Básico.

Instalei um plugin e o comando dele não existe 
E492: Não é um comando do editor: NERDTree

Causa: a pasta do plugin está no lugar errado, o gerenciador não rodou a instalação, ou o plugin está em opt/ e não foi carregado.

Solução: confira o caminho (~/.vim/pack/plugins/start/nome-do-plugin/plugin/…); com vim-plug, rode :PlugInstall; com opt/, :packadd nome; veja o que o Vim carregou com :scriptnames. Veja Plugins.

"+y não copia para o resto do sistema

Causa: seu Vim foi compilado sem área de transferência. Confira:

$ vim --version | grep clipboard
-clipboard         +jumplist          +popupwin          +user_commands
-xterm_clipboard

O - antes de clipboard quer dizer "não tem".

Solução: no Debian e no Ubuntu, instale vim-gtk3 (tem +clipboard mesmo usado no terminal); no Fedora, vim-X11; no macOS, o Vim do Homebrew. Veja Área de Transferência do Sistema.

Meu Vim não tem cores nem ajuda, e o u desfaz e refaz a mesma coisa

Causa: você está usando o vim-tiny, a versão mínima que vem instalada em muitas distribuições (no Debian e no Ubuntu, o comando vi aponta para ele). Ele não tem realce de sintaxe, ajuda completa, Vimscript nem tradução para o português, e costuma rodar no modo compatível com o vi antigo, em que o u só alterna entre desfazer e refazer a última alteração.

Solução: instale o Vim completo (no Debian/Ubuntu, sudo apt install vim; no Debian sem sudo, su -c "apt install vim") e use o comando vim. Confira com vim --version | head -3: a versão completa diz "Huge version" ou "Normal version". Veja Instalar em Qualquer Sistema.

E319: o comando não existe nesta versão 
E319: Desculpe, esse comando não está disponível nesta versão
(inglês: E319: Sorry, the command is not available in this version)

Causa: o recurso não foi compilado no seu Vim (é o caso de :let, :syntax e :function no vim-tiny).

Solução: instale o Vim completo, como no problema anterior.
