Vim Área de Transferência do Sistema

O y e o p do Vim usam registradores internos: o que você copia com yy não aparece quando você aperta Ctrl+V no navegador. Para trocar texto com outros programas, o Vim tem dois registradores especiais, + e *, ligados à área de transferência do sistema. Eles só funcionam se o seu Vim tiver sido compilado com esse suporte.

Você vai aprender
  • Descobrir se o seu Vim tem suporte (+clipboard).
  • Instalar um Vim com suporte no Linux, no macOS e no Windows.
  • Copiar e colar com "+y e "+p, e a diferença entre + e *.
  • Fazer o y e o p normais usarem a área de transferência (clipboard=unnamedplus).
  • O plano B: colar pelo terminal, sem suporte nenhum.
Esta aula não tem Vim simulado

O simulador do guia roda dentro da página e não tem acesso à área de transferência do seu computador. Os exemplos abaixo são sessões reais de terminal. Para treinar "+y e "+p, use o Vim do seu sistema.

Passo 1: o seu Vim tem suporte?

O comando vim --version lista os recursos com que o Vim foi compilado: + = tem, - = não tem. Filtrando pela palavra "clipboard":

vim --version
Mostra a versão e a lista de recursos.
|
Pipe: manda a saída para o próximo comando.
grep clipboard
Mostra só as linhas com "clipboard".

No Ubuntu recém-instalado, o comando vim nem existe: vem só o vim.tiny, que atende como vi. Ele não tem suporte:

$ vi --version | grep clipboard
-clipboard           +mouse               +terminfo       « sem suporte
-clipboard_provider  -mouseshape          +termresponse
-eval                -perl                -wayland_clipboard
+iconv               -signs               -xterm_clipboard

Depois de instalar o pacote vim-gtk3 (passo 2), o mesmo teste mostra:

$ vim --version | grep clipboard
+clipboard           +mouse               +terminal       « com suporte
+clipboard_provider  +mouseshape          +terminfo
+ex_extra            +persistent_undo     +wayland_clipboard
+insert_expand       +signs               +xterm_clipboard
RecursoSignifica
+clipboardTem os registradores + e *. É o que importa.
+xterm_clipboardConsegue usar a área de transferência pelo X11, inclusive rodando dentro de um terminal.
+wayland_clipboardConsegue usar a área de transferência do Wayland (o padrão do Ubuntu e do Fedora atuais).

Dentro do Vim, a pergunta equivalente é :echo has('clipboard'): responde 1 (tem) ou 0 (não tem). E :echo has('clipboard_working') diz se ela está funcionando agora; responde 0, por exemplo, numa sessão SSH sem interface gráfica.

A diferença entre + e * no Linux

O Linux tem duas áreas de transferência:

RegistradorÁrea no LinuxComo você usa fora do Vim
"+CLIPBOARDCtrl+C e Ctrl+V
"*PRIMARY (seleção)Selecionar com o mouse copia; o botão do meio cola

No macOS e no Windows existe uma área só, e "+ e "* são a mesma coisa. Na dúvida, use "+.

Fazendo o y e o p usarem a área de transferência

Se você quer que todo y vá para a área de transferência e todo p venha dela, sem digitar "+, ajuste a opção clipboard no ~/.vimrc:

" y, d e p usam a área de transferência do sistema (Ctrl+C / Ctrl+V)
set clipboard=unnamedplus
" no macOS e no Windows, use: set clipboard=unnamed
ValorO registrador sem nome passa a ser
unnamedplusO + (CLIPBOARD) — Linux
unnamedO * — no macOS/Windows é a área única; no Linux, a seleção
unnamed,unnamedplusOs dois ao mesmo tempo
O efeito colateral

Com unnamedplus, todo dd e x também vai para a área de transferência e apaga o que você tinha copiado no navegador. Se isso incomodar, deixe a opção desligada e use "+y só quando precisar.

Plano B: sem suporte, pelo terminal

Num servidor por SSH ou num Vim sem +clipboard, você ainda pode usar a área de transferência do terminal:

Colar texto de fora no Vim

  1. Copie o texto no navegador com Ctrl+C.
  2. No Vim, entre no modo de inserção (i ou o).
  3. Cole com o atalho do terminal: Ctrl+Shift+V no Linux, Cmd+V no macOS, clique com o botão direito no Windows Terminal.
  4. Aperte Esc.

O terminal "digita" o texto para o Vim. Nos Vims atuais isso funciona bem, porque o terminal avisa o Vim que é uma colagem (bracketed paste). Em Vims antigos ou terminais simples, a indentação automática pode transformar o código colado numa "escada":

def ola():
    print("oi")
        return True
            # cada linha ganhou mais recuo

Se acontecer, desfaça com u, ligue o modo de colagem, cole e desligue:

  1. No modo normal, digite :set paste e Enter. O Vim desliga a indentação automática.
  2. Entre no modo de inserção com i; o rodapé mostra -- INSERÇÃO (colar) --.
  3. Cole com Ctrl+Shift+V e aperte Esc.
  4. Volte ao normal com :set nopaste.

Copiar do Vim para fora

Selecione o texto com o mouse no terminal e copie com Ctrl+Shift+C. Se o Vim estiver com o mouse ligado (set mouse=a) e a seleção virar modo visual do Vim, segure Shift enquanto arrasta, para a seleção ser do terminal. Desligue os números de linha antes (:set nonumber), senão eles vão junto.

Quando não funciona

W24: Clipboard register not available 
W24: Clipboard register not available. See :h W24

O que aconteceu: você usou "+ ou "* num Vim sem +clipboard, como o vim.tiny. A mensagem aparece em inglês mesmo com o Vim em português.

Como resolver: instale o vim-gtk3 (Ubuntu/Debian) ou o equivalente do seu sistema, ou use o plano B pelo terminal.

Tenho +clipboard, mas "+p cola vazio por SSH

O que aconteceu: numa sessão SSH, o "+ é a área de transferência do servidor, que normalmente nem tem interface gráfica. :echo has('clipboard_working') responde 0.

Como resolver: use a seleção do terminal (plano B), ou copie o arquivo para a sua máquina com scp.

Apertei Ctrl+V para colar e apareceu -- VISUAL/BLOCO --

O que aconteceu: no modo normal, Ctrl+V é o modo visual de bloco do Vim, e não "colar".

Como resolver: Esc. Cole com "+p ou, no modo de inserção, com Ctrl+Shift+V.

O código colado virou uma escada

O que aconteceu: o Vim recebeu a colagem como digitação, e a indentação automática somou recuo em cada linha.

Como resolver: u, depois :set paste, cole, e :set nopaste. Melhor ainda: use "+p, que cola sem passar pela digitação.

Fedora: instalei o vim-X11 e o vim continua sem suporte

O que aconteceu: no Fedora, o Vim com suporte é outro comando: vimx.

Como resolver: abra com vimx, ou crie um apelido no ~/.bashrc: alias vim='vimx'.

Resumo

  • O y/p normal usa registradores internos; a área de transferência do sistema é o "+ (e o "*, a seleção no Linux).
  • Só funciona com +clipboard: confira com vim --version | grep clipboard.
  • No Ubuntu/Debian, instale vim-gtk3; no Fedora use vimx; no Arch, gvim; no macOS, brew install vim.
  • set clipboard=unnamedplus faz o y/p usarem a área de transferência, com o efeito colateral de todo dd ir para lá.
  • Sem suporte: cole no modo de inserção com Ctrl+Shift+V e copie com a seleção do terminal.
