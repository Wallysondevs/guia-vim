Vim Vim como IDE (LSP)

Editores como o VS Code mostram erros enquanto você digita, completam métodos sabendo o tipo de cada variável e renomeiam uma função em todos os arquivos. Quase tudo isso vem de um padrão aberto chamado LSP, e o Vim também pode usá-lo, por meio de plugins. Esta aula mostra os caminhos e uma configuração mínima que funciona.

Avançado e opcional

Você não precisa de LSP para usar bem o Vim. Autocompletar, ctags e a busca resolvem muita coisa. LSP traz dependências externas (servidores, às vezes Node.js) e mais coisas que podem quebrar. Comece por ele só quando sentir falta dos recursos de uma IDE.

Você vai aprender
  • O que é LSP e o que é um "servidor de linguagem".
  • As três opções populares no Vim: vim-lsp, coc.nvim e ALE, e quando escolher cada uma.
  • Uma configuração mínima comentada com vim-lsp, que instala os servidores para você.
  • Os atalhos do dia a dia: definição, referências, documentação, renomear, diagnósticos.
  • O que muda no Neovim, que já traz o LSP embutido.
Sobre o simulador

O Vim simulado não roda plugins. Esta aula usa arquivos de configuração e telas do Vim real.

O que é LSP

LSP (Language Server Protocol, "protocolo de servidor de linguagem") foi criado pela Microsoft em 2016. A ideia é separar duas coisas:

servidor de linguagem
Um programa que entende uma linguagem: lê o seu projeto, sabe os tipos, onde cada função foi definida, o que está errado. Exemplos: pyright (Python), clangd (C/C++), gopls (Go).
cliente
O editor. Ele só pergunta ("o que existe neste ponto?", "onde isto foi definido?") e mostra as respostas. No Vim, o cliente é um plugin.

Como todos falam o mesmo protocolo, o mesmo servidor serve ao VS Code, ao Vim, ao Neovim e a outros editores.

Todos são plugins: você precisa de um gerenciador. Os exemplos abaixo usam o vim-plug; veja como instalá-lo em Plugins.

Configuração mínima com vim-lsp

Esta configuração liga o cliente LSP, um menu de autocompletar automático e os atalhos principais. Ela segue a documentação oficial do vim-lsp.

" ---------- plugins (vim-plug) ----------
call plug#begin()
Plug 'prabirshrestha/vim-lsp'              " o cliente LSP
Plug 'mattn/vim-lsp-settings'              " instala e configura servidores
Plug 'prabirshrestha/asyncomplete.vim'     " menu de autocompletar automático
Plug 'prabirshrestha/asyncomplete-lsp.vim' " liga o menu ao LSP
call plug#end()

" ---------- atalhos que valem só em arquivos com LSP ativo ----------
function! s:ao_ligar_lsp() abort
  setlocal omnifunc=lsp#complete           " Ctrl-x Ctrl-o usa o LSP
  setlocal signcolumn=yes                  " coluna à esquerda para os avisos
  nmap <buffer> gd <plug>(lsp-definition)
  nmap <buffer> gr <plug>(lsp-references)
  nmap <buffer> K  <plug>(lsp-hover)
  nmap <buffer> <leader>rn <plug>(lsp-rename)
  nmap <buffer> [g <plug>(lsp-previous-diagnostic)
  nmap <buffer> ]g <plug>(lsp-next-diagnostic)
endfunction

augroup lsp_instalado
  autocmd!
  autocmd User lsp_buffer_registered call s:ao_ligar_lsp()
augroup END
call plug#begin() … plug#end()
A lista de plugins do vim-plug.
function! s:ao_ligar_lsp()
Uma função com os atalhos. O s: deixa o nome visível só neste arquivo.
nmap <buffer>
Atalho do modo normal que vale só no arquivo atual (veja Mapeamentos).
<plug>(lsp-definition)
Uma ação que o plugin oferece; o atalho só aponta para ela.
autocmd User lsp_buffer_registered
Roda a função quando o LSP fica pronto num arquivo (veja Autocomandos).

Repare que gd deixa de ser a busca simples do Vim (veja ctags) e passa a usar o LSP, que sabe exatamente onde está a definição.

Passo a passo

  1. Instale os plugins. Salve o .vimrc, reabra o Vim e rode :PlugInstall.
  2. Abra um arquivo da linguagem. Por exemplo, vim app.py. O vim-lsp-settings percebe que não há servidor para Python e avisa no rodapé.
  3. Instale o servidor. Rode :LspInstallServer. Ele baixa o servidor recomendado para a linguagem do arquivo aberto (para Python, um dos servidores suportados) e o guarda numa pasta do próprio plugin.
  4. Reabra o arquivo e confira com :LspStatus: o servidor deve aparecer como running.
:LspStatus
pylsp-all: running

O nome do servidor depende da linguagem e da escolha do vim-lsp-settings; a saída acima é ilustrativa.

O LspInstallServer precisa de ferramentas

Para instalar servidores, o vim-lsp-settings usa programas do sistema, como curl, unzip, git e, conforme a linguagem, python3 -m venv, npm ou go. Se a instalação falhar, a mensagem diz o que falta.

O dia a dia com LSP

Atalho (da configuração acima)ComandoO que faz
gd:LspDefinitionVai para a definição, mesmo em outro arquivo
gr:LspReferencesLista todos os lugares que usam o nome
K:LspHoverMostra a documentação e o tipo numa janela flutuante
\rn:LspRenameRenomeia em todo o projeto
]g / [g:LspNextDiagnosticPróximo / anterior erro ou aviso

O \rn usa a tecla leader, que por padrão é a barra invertida (\). Os erros aparecem na coluna da esquerda e, conforme a configuração, como texto ao lado da linha:

  1 import os
E 2 print(nome_errado)          « Undefined name `nome_errado`
  3 os.getcwd()

O texto exato do aviso vem do servidor, normalmente em inglês.

Alternativa: coc.nvim

Apesar do nome, o coc.nvim funciona no Vim e no Neovim. Ele exige Node.js instalado e numa versão recente (confira a versão mínima no README do projeto).

call plug#begin()
" a branch 'release' já vem compilada; sem ela o coc não funciona
Plug 'neoclide/coc.nvim', {'branch': 'release'}
call plug#end()

nmap <silent> gd <Plug>(coc-definition)
nmap <silent> gr <Plug>(coc-references)
nmap <leader>rn <Plug>(coc-rename)
:CocInstall coc-pyright coc-tsserver coc-json

Cada coc-… é uma extensão para uma linguagem. :CocInfo mostra a versão do Node em uso e os erros, se houver.

Alternativa: ALE para lint e formatação

O ALE (Asynchronous Lint Engine) roda verificadores (linters) e formatadores enquanto você edita. Ele usa os programas que já estão instalados no sistema, como flake8, shellcheck ou prettier.

call plug#begin()
Plug 'dense-analysis/ale'
call plug#end()

" quais verificadores usar em cada linguagem
let g:ale_linters = {'python': ['flake8'], 'sh': ['shellcheck']}
" quais formatadores usar
let g:ale_fixers = {'python': ['black'], '*': ['trim_whitespace']}
" formata ao salvar
let g:ale_fix_on_save = 1

Dá para combinar: ALE para verificar e formatar, vim-lsp ou coc.nvim para navegação e autocompletar. Nesse caso, desligue o LSP do ALE com let g:ale_disable_lsp = 1 para os dois não mostrarem os mesmos erros.

E no Neovim?

O Neovim já traz um cliente LSP embutido, configurado em Lua. A partir do Neovim 0.11 basta descrever o servidor e ativá-lo; plugins como nvim-lspconfig trazem as configurações prontas e o mason.nvim instala os servidores.

-- Neovim 0.11 ou mais novo, com o plugin nvim-lspconfig instalado
vim.lsp.enable('pyright')

-- atalhos: no Neovim 0.11, K, grn (renomear) e grr (referências) já vêm prontos
vim.keymap.set('n', 'gd', vim.lsp.buf.definition)

Se o seu objetivo principal é ter LSP com o mínimo de esforço, o Neovim é o caminho mais direto. Os comandos de edição são os mesmos do Vim.

Quando não funciona

"Função desconhecida: plug#begin" 
Erro detectado ao processar /home/ana/.vimrc:
linha    2:
E117: Função desconhecida: plug#begin

O que aconteceu: o vim-plug não está instalado.

Como resolver: instale o vim-plug (veja Plugins) e rode :PlugInstall.

:LspInstallServer não existe 
E492: Não é um comando do editor: LspInstallServer

O que aconteceu: o plugin mattn/vim-lsp-settings não foi instalado, ou você ainda não rodou :PlugInstall depois de editar o .vimrc.

Como resolver: :PlugInstall, feche e abra o Vim de novo.

Nada acontece: sem erros, sem autocompletar

O que aconteceu: o servidor não está rodando para este tipo de arquivo.

Como resolver: confira o tipo com :set filetype? (deve ser, por exemplo, python) e o servidor com :LspStatus (vim-lsp) ou :CocInfo (coc.nvim). Os registros do vim-lsp ficam num arquivo definido por let g:lsp_log_file = expand('~/vim-lsp.log').

coc.nvim reclama do Node

O que aconteceu: o Node.js não está instalado ou é antigo demais.

Como resolver: instale uma versão recente do Node e confira com node --version no terminal. Se preferir não depender do Node, use vim-lsp.

O Vim ficou lento depois do LSP

O que aconteceu: servidores de linguagem analisam o projeto inteiro, o que pesa em projetos grandes ou em máquinas modestas.

Como resolver: abra o Vim na pasta do projeto (não na pasta pessoal inteira), desative o que não usa e considere ALE, que é mais leve, só para lint.

Resumo

  • LSP separa o editor (cliente) de quem entende a linguagem (servidor).
  • No Vim, o cliente é um plugin: vim-lsp (leve), coc.nvim (completo, com Node) ou ALE (lint e formatação).
  • Com vim-lsp-settings, :LspInstallServer baixa o servidor certo para você.
  • Os atalhos clássicos: gd definição, gr referências, K documentação, renomear e ]g erros.
  • É opcional: comece sem LSP e adicione quando sentir falta.
