Vim Editar Configurações de Servidor

Este é o motivo número um de muita gente aprender Vim: você entra num servidor por SSH e precisa mudar uma linha de configuração. Não há mouse nem editor gráfico, e o Vim (ou o vi) está sempre lá. Neste laboratório você edita cópias de mentira de um sshd_config e de um nginx.conf, como faria num servidor de verdade.

Você vai aprender
  • Achar a linha certa num arquivo grande com /.
  • Trocar um valor com cw e com :s.
  • Descomentar uma linha com x e várias de uma vez com :s/^#//.
  • Comentar um bloco inteiro com Ctrl+V e I#.
  • Editar arquivos do sistema com segurança usando sudoedit e testar a configuração antes de aplicar.
Antes de começar

Você vai usar Buscar, Operadores, Substituir e Modo Visual de Bloco. Se algum comando parecer estranho, a aula dele está no link.

O roteiro

  1. Proibir o login direto do root (PermitRootLogin no).
  2. Descomentar a porta e trocar para 2222.
  3. Desligar o login por senha com :s.
  4. Descomentar várias linhas de uma vez.
  5. No nginx.conf, comentar um bloco location inteiro.
  6. Ajustar dois valores e salvar.

Etapa 1: achar a linha e trocar o valor

Num arquivo de configuração real há dezenas de linhas. Rolar com j até achar é lento. O jeito Vim é buscar: /, o texto e Enter. O cursor pula para a primeira ocorrência.

/Root
Busca o texto "Root". Ele está dentro de PermitRootLogin; não precisa digitar a palavra inteira.
<Enter>
Confirma a busca. O cursor vai para o "R".
w
Pula para a próxima palavra: o yes.
cw
Troca (change) a palavra: apaga yes e entra no modo de inserção.
no<Esc>
Digita o novo valor e volta ao modo normal.
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6

Repare que, ao apertar Enter, o rodapé mostra /Root: é o Vim confirmando o que buscou. Agora faça você:

# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6
# Configuração do servidor SSH
#Port 22
PermitRootLogin no
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6

Missão: troque PermitRootLogin yes por PermitRootLogin no, sem usar as setas.

Ver uma solução

/Root<Enter> leva o cursor até a linha; w vai para o yes; cwno<Esc> troca a palavra. Total: 12 teclas.

Etapa 2: descomentar e mudar a porta

Em arquivos de configuração, o # no começo da linha transforma a linha em comentário: o programa ignora. Para ativar a opção, basta apagar o #, e o x faz isso com uma tecla.

/#Port<Enter>
Vai até a linha #Port 22, com o cursor sobre o #.
x
Apaga o #: a linha vira Port 22.
$
Vai para o último caractere da linha, o 2 final.
a22<Esc>
Acrescenta (append) 22 depois do cursor: 22 vira 2222.
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6
# Configuração do servidor SSH
Port 2222
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6

Missão: descomente a linha da porta e troque 22 por 2222.

Ver uma solução

/#Port<Enter>x$a22<Esc> (13 teclas). Outra forma: /#Port<Enter>x e depois wcw2222<Esc>.

Mudou a porta do SSH num servidor de verdade?

Libere a porta nova no firewall antes de reiniciar o SSH, e não feche a sessão atual até testar a conexão pela porta nova em outro terminal. Senão você perde o acesso.

Etapa 3: trocar com :s

O cw é ótimo quando o cursor já está na palavra. Outra forma é o comando :s (de substitute, substituir), que troca um texto por outro na linha atual, sem precisar mover o cursor até a palavra.

/Password<Enter>
Leva o cursor até a linha certa.
:s
Substituir, na linha do cursor.
/yes
O que procurar.
/no/
Pelo que trocar.
<Enter>
Executa.
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication no
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6

Missão: desligue o login por senha (PasswordAuthentication no) usando :s.

Ver uma solução

/Password<Enter> e depois :s/yes/no/<Enter>. Sem a busca antes, o :s atuaria na linha 1, que não tem "yes", e o Vim avisaria E486: Padrão não encontrado: yes.

Senha desligada só com chave funcionando

No servidor real, só desligue o login por senha depois de entrar com sua chave SSH com sucesso. Senão, ninguém mais entra.

Etapa 4: descomentar várias linhas de uma vez

Quando são muitas linhas, apagar # por # cansa. O :s aceita uma faixa de linhas antes do s, e o ^ significa "começo da linha".

:2,$
Faixa: da linha 2 até a última ($). A linha 1 é um comentário de verdade e deve continuar comentada.
s/^#//
Troca o # do começo da linha (^#) por nada.
<Enter>
Executa em todas as linhas da faixa. Linhas sem # no começo ficam como estão.
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6
# Configuração do servidor SSH
#Port 22
PermitRootLogin yes
PasswordAuthentication yes
#PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6
# Configuração do servidor SSH
Port 22
PermitRootLogin yes
PasswordAuthentication yes
PubkeyAuthentication yes
X11Forwarding yes
MaxAuthTries 6

Missão: descomente todas as opções, mas deixe a linha 1 como comentário.

Ver uma solução

:2,$s/^#//<Enter>. Com :%s/^#// (o arquivo inteiro), a linha 1 também perderia o #.

Etapa 5: comentar um bloco no nginx.conf

Agora o contrário: desativar um bloco inteiro do nginx sem apagá-lo, para poder voltar atrás depois. O modo visual de bloco seleciona uma coluna, e o I escreve o mesmo texto no começo de todas as linhas selecionadas.

/location<Enter>
Vai até a linha do bloco.
0
Vai para a coluna 1 da linha.
<Ctrl-V>
Começa a seleção em bloco (retângulo).
jj
Estende a seleção duas linhas para baixo: três linhas no total.
I#
Insere # no começo do bloco. Enquanto você digita, só a primeira linha muda.
<Esc>
Ao sair, o Vim copia o # para todas as linhas do bloco.
server {
    listen 80;
    server_name exemplo.com;
    location /antigo {
        return 301 /novo;
    }
}

Avance tecla por tecla e veja: depois do I# só a primeira linha tem #; o Esc completa as outras duas.

server {
    listen 80;
    server_name exemplo.com;
    location /antigo {
        return 301 /novo;
    }
}
server {
    listen 80;
    server_name exemplo.com;
#    location /antigo {
#        return 301 /novo;
#    }
}

Missão: comente as três linhas do bloco location com # na primeira coluna.

Ver uma solução

/location<Enter>0<Ctrl-V>jjI#<Esc>. Outra forma: :4,6s/^/#/<Enter>, em que ^ é o começo da linha e o # entra no lugar dele.

Etapa 6: ajustar valores e salvar

Duas mudanças comuns no nginx.conf: deixar o nginx escolher o número de processos (auto) e aumentar o número de conexões. Para o número, existe um truque: Ctrl+A soma ao número sob o cursor ou à frente dele. 256 seguido de Ctrl+A soma 256.

w
Da coluna 1, pula para o 1 de worker_processes 1;.
cwauto<Esc>
Troca 1 por auto. O ; fica, porque não faz parte da "palavra".
/768<Enter>
Vai até o número de conexões.
256<Ctrl-A>
Soma 256: 768 vira 1024.
:w<Enter>
Salva (write). O rodapé confirma com "nginx.conf" 4L, ...B gravado(s).
worker_processes 1;
events {
    worker_connections 768;
}
worker_processes auto;
events {
    worker_connections 1024;
}

Missão: troque 1 por auto, mude 768 para 1024 e salve. Enquanto não salvar, a missão avisa "falta salvar com :w".

Ver uma solução

wcwauto<Esc>/768<Enter>256<Ctrl-A>:w<Enter>. Sem o truque do Ctrl+A: /768<Enter>cw1024<Esc>.

No servidor de verdade

Arquivos em /etc pertencem ao root. Abrir com sudo vim funciona, mas roda o Vim inteiro como administrador, com seus plugins e configurações. O jeito mais seguro é o sudoedit: ele copia o arquivo para uma pasta temporária, abre a cópia no seu editor como usuário comum e só grava de volta quando você sai.

$ export EDITOR=vim          « o sudoedit usa o editor desta variável
$ sudoedit /etc/ssh/sshd_config
$ sudo sshd -t               « testa a configuração; sem saída = tudo certo
$ sudo systemctl reload ssh

O sshd -t (de test) lê o arquivo e avisa se algo está errado, sem mexer no serviço. Se você digitou uma opção errada, ele mostra a linha:

$ sudo sshd -t
/etc/ssh/sshd_config: line 3: Bad configuration option: PermitRootLogn
/etc/ssh/sshd_config: terminating, 1 bad configuration options

Abra de novo com sudoedit, vá direto à linha com :3 e corrija. Com o nginx é igual: teste com nginx -t antes de recarregar.

$ sudoedit /etc/nginx/nginx.conf
$ sudo nginx -t
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
$ sudo systemctl reload nginx
Nomes de serviço

No Debian e no Ubuntu o serviço do SSH se chama ssh; no Fedora, no Rocky e no Arch, sshd. As mensagens do sshd -t acima são as típicas do OpenSSH e podem variar um pouco de versão para versão.

Abrir o arquivo já na linha certa

vim +3 arquivo abre com o cursor na linha 3, e vim +/PermitRoot arquivo abre já na primeira ocorrência do texto.

Quando não funciona

Rodapé mostra [somente-leitura] e o :w não grava 
$ vim /etc/ssh/sshd_config

Ao tentar salvar, o Vim responde E45: opção 'readonly' está definida (adicione ! para forçar). Se você forçar com :w!, vem E212: Impossível abrir arquivo para escrita.

O que aconteceu: você abriu um arquivo do root como usuário comum. O Vim deixa ler, mas o sistema não deixa gravar.

Como resolver: saia sem salvar (:q!) e abra com sudoedit. Se já fez muitas alterações, salve uma cópia na sua pasta com :w ~/sshd_config.novo e copie depois com sudo cp.

E486: Padrão não encontrado

O que aconteceu: o texto buscado não existe exatamente assim. A busca diferencia maiúsculas de minúsculas: /permitroot não acha PermitRootLogin.

Como resolver: confira a grafia, ou termine a busca com \c para ignorar maiúsculas: /permitroot\c. Veja Buscar.

O I# só comentou a primeira linha

O que aconteceu: o bloco foi feito com v ou V em vez de Ctrl+V, ou você saiu com as setas em vez de Esc.

Como resolver: u para desfazer e repita com Ctrl+V, terminando com Esc. Em alguns terminais do Windows, Ctrl+V cola texto; use Ctrl+Q, que faz o mesmo no Vim.

Resumo

  • /texto leva direto à linha; não role a tela procurando.
  • cw troca o valor sob o cursor; :s/velho/novo/ troca na linha atual.
  • x descomenta uma linha; :2,$s/^#// descomenta várias.
  • Ctrl+V, jj, I#, Esc comenta um bloco.
  • No servidor: sudoedit para editar, sshd -t ou nginx -t para testar, e só então recarregar.
